### 2.2 统一 ORT 解析入口（§7.2）

- 新增 `scripts/resolve-ort.ps1`：**库+CLI 双面**统一入口，探测/校验/下载

  1. caller 显式 `SHERPA_ONNX_LIB_DIR`/`ORT_LIB_PATH` 优先；
  2. 稳定机器缓存 `%LOCALAPPDATA%\OwO\Agent\runtime\<ver>` →

  3. 校验 `onnxruntime.lib` 存在+尺寸，报告 v1.13.5 static-MT win-x64 +
     归档 sha256；
  4. **只注入当前进程**（SHERPA_ONNX_LIB_DIR/ORT_LIB_PATH/
     ORT_LIB_LOCATION 三个消费面全注入；历史脚本只设其一属不完整）；
  5. 缺失立即 throw 可操作错误（附 `-EnsureOrt` 指引），不等 LNK1120。
- 调用方收口（同入口）：`ci-gate.ps1`、`gate.ps1`、`package-desktop.ps1`、
  `build-installer.ps1`、`release-artifact-manifest.ps1`、

- **修复 dot-source 污染回归**（本批实测抓到）：resolve-ort 顶层

### 2.3 发布构建约束（§7.3）

- `build.rs` release 门禁：profile=release 且非
  `OWO_ALLOW_DIRTY_RELEASE=1` 时，commit 不可解析 / dirty / epoch=0
  直接 panic 拒绝。
- **dirty 统一口径 = 构建作用域 agent-sdk/**（tracked 改动 + agent-sdk 内
  未跟踪；仓根个人文档/素材等与构建无关的 untracked 资产不拦截发布）——
  同步 `build.rs`、`Assert-OwoCleanTree`、`Write-OwoBuildInfo`、
  `release-artifact-manifest.ps1`、`run-v1-acceptance.ps1` 五处。
  不这么做的后果：本机 40+ 仓根个人资产让 release 门禁永远误锁，
  被迫常开豁免开关，门禁形同虚设。
- `build-installer.ps1`/`package-desktop.ps1` linker 零容忍升级：
  任意 `LNK\d{4}` 或 `warning: linker` 行按发布失败；唯一豁免 MSVC
  工具链信息性 `正在创建库/Creating library`（windows-msvc 链接 exe
  必打、经 rustc linker_messages 包装，与 CRT 混用无关——不放行则
  一切发布构建 100% 误杀）。
- `build-installer.ps1`：sidecar 复制后立即 SHA-256 核对（复制损坏零窗口）。
- `release-artifact-manifest.ps1` schema 1→**2**：
  - 拒绝 dirty 树（第二道闸，豁免如实记录 `dirty_override`）；
  - 身份段改从**已构建产物 `--version` 输出**解析（证明清单记录的是二进制
    自身主张而非脚本重新 git 查询的巧合一致），并与当前树交叉核对，
    commit 错配即失败；
  - 新增 `dependencies` 段：rustc/cargo/target + ORT（版本/资产/CRT/
    归档 sha256/解析来源），经统一入口报告。

### 本批发现并修复的门禁外缺陷

1. **BOM 剥离**：`edit` 类工具写 .ps1 会丢 UTF-8 BOM（上一会话 5 脚本
   裸奔进工作树，UTF-8 门禁「.ps1 需带 BOM」必红；PS 5.1 下中文脚本
   无 BOM = GBK 误读风险）。全部恢复，批量扫描 agent-sdk 无漏网。
   **纪律：每次编辑 .ps1 后必须复验 BOM。**
2. **EAP 泄漏假红**（见 2.2）：教训是 dot-source 的库不得改调用方
   会话偏好；ci-shared 的 catch 分支把首行 stderr 进度当失败详情暴露
   了这一点。
3. **dirty 口径脱离现实**：全树 porcelain 会把仓根个人资产算进构建身份，
   release 门禁永不可过——统一为 agent-sdk/ 构建作用域（五处同步）。
4. **dot-source param 类型污染（5e433ce 修，实测定位链最长的一条）**：
   resolve-ort 顶层 `[switch]$Json` 经 dot-source 注入调用方作用域并
   **绑定即定型**（PS 变量名不区分大小写）→ release-manifest 脚本
   `$json = ConvertTo-Json ...` 对 string 做 String→SwitchParameter 强制
   转换，报 ArgumentTransformationMetadataException——同数据换显式
   `-InputObject` 三连干净、管道形态稳定红，插桩二分「子对象全 OK、
   整体 FAIL」全部吻合「失败在赋值、不在 cmdlet」的真相。同族第二例：
   裸名 `$EnsureOrt` dot-source 注入把 **ci-gate 自己的 -EnsureOrt
   静默重置 $false**（下载开关失效无报错，比红更糟）。修复=统一入口
   两脚本顶层参数全 `$Owo` 前缀 + `[Alias]` 保原 CLI 面；manifest
   另加逐键重建回退（发布清单零随机红）。**纪律：库脚本禁止裸名
   顶层参数。**
5. **init-dev-env 存量 bug 顺带**：直接执行分支从未转发 `$EnsureOrt` →
   `-File init-dev-env.ps1 -EnsureOrt` 此前永不触发下载（现修复实测）。
6. **Get-ExeVersion 取段修正**：clap `--version` 渲染 `"<bin> <version>
   api=…"`——首段是 bin 名；版本号取首个数字打头段。

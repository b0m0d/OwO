# 权限档位扩展与工具引入 — 设计开发文档（2026-09-30）

> 需求：① `/permissions` 增加自动审批与「完全权限（越界文件访问 + 命令执行）」；
> ② 工具是否自研、是否引入成熟高性能工具（ripgrep 等）。

## 1. 现状盘点

### 1.1 权限档位（core `owo-agent-policy::permissions`）

| 档位 | 行为 | 越界文件 |
|---|---|---|
| `read_only` | 全部拒绝（只读） | 拒绝 |
| `workspace`（默认） | 读放行；写/执行询问 | **拒绝**（`evaluate` 阶段 `拒绝：路径越界`） |
| `auto_review` | 审批 Agent 可代批可代批操作 | 拒绝 |
| `full_access` | Write/Execute 放行（工作区内），Inject 询问 | 拒绝 |
| `custom` | 按 spec 规则 | 拒绝 |

**关键结论**：现有 `full_access` **不能越界**——工作区边界在 `Policy::evaluate_with_effect`
里是硬拒绝（`reason` 以「拒绝」开头 → `decision()` 恒 Deny）。用户要的"完全权限"需要新档位。

沙箱层（`owo-agent-tool-safety::SandboxPolicy`）已具备高风险开关：
`FileScope::Unrestricted` + `allow_unrestricted_file`、`NetworkPolicy::Unrestricted` +
`allow_unrestricted_network`（`validate()` 强制显式放行）。**缺口是档位→沙箱策略的接线**。

### 1.2 工具现状

| 工具 | 实现 | 说明 |
|---|---|---|
| `read_file` / `write_file` | 自研 | 工作区路径校验 |
| `list_dir` | 自研 | `tokio::fs::read_dir`，无排序/上限 |
| `search_files` | **随包 ripgrep**（`--files` 文件名检索） | `external_tools::resolve_ripgrep`，版本/哈希固定 |
| `run_command` | 自研 + 沙箱 | `cmd /C`，60s/1GB/Job 隔离 |
| MCP / 桌面 / 浏览器 | 适配层 | — |

**缺口**：`search_files` 只搜**文件名**，没有**内容检索（grep）**。ripgrep 已随包，直接复用即可。

## 2. 设计

### 2.1 新档位 `unrestricted`（高风险，显式 opt-in）

- `PermissionProfile::Unrestricted`（label `unrestricted`；`parse` 兼容 `danger_full_access`）。
- `evaluate_with_effect`：越界文件路径在 `unrestricted` 下不再拒绝，reason 标注「工作区外」。
- `decision`：Read/Write/Execute → Allow；**Inject 仍 Ask**（不可逆操作保留确认）。
- **不绕过**：deny 片段（危险命令）、`extra_denial` 维度收紧、审计、秘密脱敏。
- 沙箱接线：`run_command` / `grep` / `search_files` 在 `unrestricted` 下把
  `file_scope=Unrestricted`、`allow_unrestricted_file=true`，并显式打开网络
  （`allow_unrestricted_network=true`）；其余档位保持工作区沙箱。

### 2.2 CLI `/permissions`

- 两条 REPL 统一：`/permissions` 查看当前档位；`/permissions set <profile>` 切换。
- Daemon 路径接 `POST /permissions {"profile": …}`（服务端已有，写入 settings.json + 运行时生效）。
- 高风险档位（`unrestricted`/`full_access`）切换前给醒目警告；`unrestricted` 在交互终端需
  `y` 确认，管道模式需显式 `--yes`。

### 2.3 新增 `grep` 工具（内容检索）

- 复用随包 ripgrep：`rg --line-number --no-heading --color never --max-columns 300
  --glob !.git/** --glob !target/** --glob !node_modules/** -e <pattern> [path]`。
- 参数：`pattern`（必填）、`path`（可选，默认工作区）、`glob`（可选）、`max_results`（默认 100）。
- 输出：`{pattern, matches:[{path,line,text}], truncated, tool:"ripgrep", tool_version}`。
- 安全：只读（`EffectClass::Read`）、沙箱 Job 隔离、30s/512MB、越界路径按档位处理。
- 注册：默认注册表 + `builtin_class_for`/`builtin_effects` 增加 `grep`。

## 5. 风险

- `unrestricted` 等价 Codex `danger-full-access`：默认关闭、显式确认、审计留痕；文档与 UI 明确标注。
- 网络放开仅随 `unrestricted` 生效，不改变 `OWO_CLOUD_ENABLED` 的云端开关语义。

## 6. 工具链质量补齐（第二批，2026-09-30）

六项缺口全部落地（工具总数 37 → **45**，其中内置矩阵 34 → 42）：

| 工具 | 说明 |
|---|---|
| `apply_patch` | Codex 风格多文件补丁（`*** Add/Update/Delete File:` + `@@` 段落）；先全量解析校验再落盘，写入走快照可 diff/revert；上下文必须唯一命中 |
| `edit_file` | 精确替换（`old_string`→`new_string`，默认唯一命中，`replace_all` 全替换） |
| `read_file` | 新增 `offset`/`limit`（默认 400，上限 2000）与 `number` 行号；返回 `start_line/end_line/total_lines/truncated` |
| `todo` | 会话级任务清单（整表替换，`pending/in_progress/completed`），CLI `/todo` 渲染 ✔/▶/○ |
| `web_fetch` / `web_search` | 轻量 HTTP：20s 超时、256KB 上限、HTML→文本；搜索默认 DuckDuckGo HTML，可用 `OWO_WEB_SEARCH_URL` 覆盖；网络出口按 `Execute` 级审批 |
| `read_image` | 图片元数据 + base64（4MB 上限；多模态视觉需 gateway 图像支持，已在返回值注明） |
| `run_command background` + `shell_output` + `kill_shell` | 后台 shell：包装脚本 + 工作区内日志，watcher 任务等待退出，句柄注册表支持 kill |

### 6.1 冒烟中发现并修复的两个真实缺陷

1. **`resolve_session_path` 拒绝工作区内绝对路径**：`\\?\C:\…`（verbatim）与 `C:\…` 混用时
   `starts_with` 恒不匹配 → 绝对路径被误判"路径越界"。修复：绝对路径直接采用、两侧统一去
   verbatim 前缀再比对；并让 `unrestricted` 档位真正放行越界路径（此前策略层放行、工具层仍拒绝）。
2. **`run_command` 无法执行任何外部命令**：Job `active_process_limit = 1`，而 `cmd /C ping`
   至少占 2 个进程（cmd + 子进程）→ "Not enough quota to process this command"。修复：
   run_command 放宽到 16（仍兜住进程炸弹）。
3. 后台 shell 三个坑：日志写 `%TEMP%`（工作区外，沙箱拒绝）→ 改为工作区 `.owo/shells/`；
   嵌套引号被沙箱参数引用破坏 → 改用包装脚本 `.cmd`；`\\?\` 前缀在沙箱 cmd 重定向下失败 →
   去 verbatim 前缀。

### 6.3 已知限制

- `todo` 暂不落 SQLite（会话内存态；`/fork` 继承，重启后清空）。
- `read_image` 返回 base64，但 gateway 目前是纯文本协议，模型无法"看图"；接入多模态需扩展
  `ChatMessage` 内容部件与 provider 序列化。
- `web_search` 依赖 DuckDuckGo HTML 结构，可能随对方改版失效；生产建议配置 `OWO_WEB_SEARCH_URL`。
- 后台 shell 日志在工作区 `.owo/shells/`，不随会话清理（可加保留策略）。

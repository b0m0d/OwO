### 3. 缺陷、根因与修法

1. **release clean-tree 门被架空**（`owo-build-info/build.rs`）
   `git -C <agent-sdk> status --porcelain -uall -- agent-sdk` 的 pathspec 相对 `-C`
   目录解析成 `agent-sdk/agent-sdk` → 永远为空 → **dirty 恒为 false**。R2 报告里的
   "干净树"主张因此是假的。修法：pathspec 改 `-- .`（与 SDK 目录名/深度解耦），并
   用 `git rev-parse --show-toplevel` 得到真实 `.git` 后再报 `rerun-if-changed`
   （原来指向不存在的路径 → 构建脚本每次都重跑）。
   实测探针：错误作用域 `git status` 输出 0 行，正确作用域 19 行——直接坐实。
2. **桌面壳 workspace 不在任何门禁内**（`src-tauri/build.rs`）
   R2 把 `OWO_API_VERSION` 改成 re-export 后，壳的 build.rs 仍用正则从 server 源码
   抓字面量 → 壳**根本编译不过**，而所有"全绿"记录都不含壳。修法：改从
   `owo-build-info` 读 `API_VERSION`，并断言 server 侧只能 re-export、禁止字面量
   （§7.1 单源）；`ci-gate` 增加桌面壳四步。
3. **安装包持续打包旧 core**（`binaries/` externalBin）
   `build-installer.ps1` 把新 core 复制成 `owo-agent.exe-x86_64-pc-windows-msvc.exe`，
   而 Tauri 只认 `owo-agent-<triple>.exe` → 新文件无人读，安装包实际打的是
   `binaries/` 里另一份 8/31 的无身份残留（"SHA-256 核对通过"核对的是错名文件）。
   修法：唯一入口 `stage-desktop-sidecar.ps1`（清残留 → 正确命名复制 → 哈希核对 →
   `--version` 身份核对 → 与源身份一致），`build-installer.ps1` 与 `ci-gate` 同源
   调用；`src-tauri/build.rs` 增加构建期硬门（错命名直接 panic；无 `commit=` 拒绝；
   `api` 与壳期望不一致拒绝；release 下 commit ≠ HEAD 拒绝）。
   门的双向验证：正例 `cargo check` 0 错；放入错名文件 → build.rs panic 且文案可操作。
4. **手写 cargo 命令静默挂死**（环境）
   新进程无 ONNX Runtime 变量时 `ort-sys`/`sherpa-onnx-sys` 退化为联网下载，在受限
   沙箱内 15 分钟零 CPU、无 `rustc`、无报错。修法：写入 `AGENTS.md` 硬规则
   （任何手写 `cargo` 前必须 dot-source `resolve-ort.ps1` + `Resolve-OwoOrtEnv -Quiet`）。

### 4. 协议/持久化/CLI/UI 变化

- 无 HTTP 路由、DTO、CLI 参数、UI 协议变化。
- 构建语义变化：dirty 判定生效后，未提交改动树上的 release 构建会**真的失败**
  （此前静默通过）；`--version` 的 `built_at` 语义是"身份被计算的时刻"，不是
  链接时刻——判断产物新鲜度一律用 SHA-256，不用时间戳（已在验收脚本落实）。

### 5. 权限、秘密、工作区、网络、不可恢复操作影响

- 不引入任何秘密；模型密钥路径不变（仅环境变量注入）。
- `stage-desktop-sidecar.ps1` 只写 `src-tauri/binaries/`（gitignored 构建输入），
  并在复制前删除该目录下 `owo-agent*` 残留——删除范围严格限定在这一个目录，
  且只删构建产物，不触碰源码或用户数据。
- build.rs 会执行随包 exe 的 `--version`（本机进程 spawn，不联网）。

### 3. 协议变化（对外可见）

- 新路由 `GET /diagnostics/requests?limit=`（**受保护面**，匿名 401；公开面不变，
  由既有 `public_surface_is_exactly_health_openapi_bootstrap` 契约测试守护）。
- 记录字段**恰好六项**：`method/route_template/started_at/duration_ms/status/source`；
  不落原始 path、查询串、token、body；`source` 来自 `x-owo-client` 头，按
  `[a-z0-9_-]{1,32}` 消毒，异常值归 `other`。环形 512 条，按 `data_root` 键控。
- 访问日志停止输出原始 `path`（改记 `route_template`），trace 头统一 `x-trace-id`，
  CORS 允许头新增 `x-owo-client` 与 `x-trace-id`。
- **SSE 缺省语义变更**：`GET /events/stream` 无 `Last-Event-ID`/`?last_event_id=`
  时**不再重放整环历史**（新订阅只收实时事件）；显式 `?last_event_id=0` 保留
  "全量重放"逃生口。断线续传语义不变（既有 header 续传测试仍绿）。
- **bearer 语义变更**：`AuthToken` 每次进程启动换发并覆盖写
  `<data_root>/auth/token`；上一代 bearer 在新代际一律 401。文件仍是外部工具的
  发现通道（读到的永远是当前代际值）。

### 4. 为什么必须改 SSE 与 token（实测因果）

- 首屏业务请求实测 **19 条**（证据 `docs/qa/evidence/r3-cold-boot-20260917-221608/`）
  远超 §8.2 的 ≤5。台账定位到两个叠加根因：① 服务端缺省从头重放 → WebView 一连上
  就收到整环失效事件，14 个域各刷一次；② web 侧事件流 URL 被双前缀拼坏 → 连接失败
  进 Degraded → 立即全量冲刷。二者任缺一都会造成风暴，故两侧同修。
- token 换发是 §8.2 第 5 条的字面要求；旧实现"文件存在即复用"使上一代泄漏的
  bearer 长期有效，桌面端只是被壳推送新凭据掩盖了症状。

### 5. 权限、秘密、工作区、网络、不可恢复操作影响

- 台账是**新增可观测面**且受保护：不放宽任何鉴权；隐私由契约测试逐字节断言
  （记录里不得出现资源 id 标记、查询串、token 值、密钥字串、静态资产名）。
- 不落盘请求体、不落盘 header 原值；环形缓冲有界（512）防内存增长。
- token 换发不改变权限模型（默认 deny 不变），只改变凭据生命周期。

## R3.3 桌面壳与 WebView 的重连正确性

### 1. 本批唯一目标

让"壳重启 core / core 换发凭据"在真实桌面上自动恢复，而不是表现为超时或永久失联。

### 2. 精确修改文件

`desktop/tauri/src-tauri/src/{core_runtime.rs,core_supervisor.rs,main.rs}`、
`desktop/web/core/{api-client.js,events.js}`、`desktop/web/app.js`、
`desktop/web/shell/connection.js`、`desktop/web/tests/{api-client,events,boot-hydrate,boot-http-count}.test.mjs`。

### 3. 行为变化与根因

1. **壳拒绝无构建身份的 core 候选**：`core_server_path()` 返回
   `(Option<PathBuf>, Vec<PathBuf>)`——同目录/SDK 候选逐个用 `--version` 探测
   `commit=`（非 unknown）+ `built_at=`；无身份者进"被拒绝清单"并写壳日志，全部
   不可用即 `core/binary_missing`。修的是"同目录优先被 8/31 手工残留劫持 →
   40s 握手超时的莫名失败"（把含糊超时变成明确拒绝）。探测带
   `CREATE_NO_WINDOW`，不弹窗。
2. **web 出口自带来源标签**：`x-owo-client: web`（含事件流与 token 引导路径）；
   壳侧 HTTP 同样带 `shell`，`/diagnostics/requests` 才能分桶归因。
3. **事件流 URL 组装修正**：向宿主传**路径** + `opts.url` 诊断字段，消除
   base 双前缀；`startPollFallback()` 首个 tick 延迟一个周期（此前"连接装配失败
   → 立即全量刷新"会在首屏叠一整轮 14 域请求）。
4. **失效器按实例身份幂等**：`startInvalidation` 键改为 `base#coreInstanceId`
   （core 重启后端口可能被系统复用，仅比 base 会留着上一代订阅器，其
   `Last-Event-ID` 游标属于旧进程 → 新版本号落在游标下被当 duplicate 丢弃）。
5. **运行期重握手**（本批最后一块真缺口）：core 重启会同时换端口与 bearer，
   打到旧端口的是**网络错误**，压根到不了 401 分支。现在
   `ApiClient.handleNetworkFailure()` 在连接层失败时整体 `resetCoreConnection()`
   （带 1s 冷却防风暴）并重试一次；`shell/connection.js` 在 `owo:connection ready`
   时重建失效器。此前恢复单飞只在"启动失败"分支建立，运行期重启等于永久失联。
6. **壳测试串行化**：两个 `with_isolated_data_dir` 测试并发改全局 `LOCALAPPDATA`
   造成偶发失败，加一次性串行锁并恢复原值。
7. **桌面后台态接管（本批最后一块真缺陷）**：实测两条事实——
   - 外部 `ShowWindow(SW_HIDE)`：窗口在 Win32 层隐藏，`document.visibilityState`
     仍是 `"visible"`；
   - 壳自己的 `window.hide()`（wry `set_visible(false)` = `SW_HIDE` +
     `controller.SetIsVisible(false)`）：Win32 层隐藏成功，
     `document.visibilityState` **依旧是 `"visible"`**（探针输出
     `after hide: vis=visible hidden=False win32=False`）。

   结论：桌面端所有以 `document.visibilityState === "hidden"` 为准的守卫
   （`scheduleRefresh` 暂停、事件失效延后 deferred、兜底轮询跳过、隐藏期请求计数）
   在真实壳里**全是死代码**——隐藏 5 分钟里 30s 健康轮询照打 10 次即为证据。
   修法：壳在隐藏/唤回时把事实注入页面（`main.rs::sync_window_background` →
   `webview.eval("window.owoSetBackground(true|false)")`），前端以
   `uiHidden() = 壳标记 || document.visibilityState` 为**唯一口径**，三个守卫点
   与 `bumpRequestStat` 全部改走它；回到前台由 `invalidator.onVisibility()`
   补刷隐藏期间攒下的域失效（恰好一次）。同时把 `owo:visibility` 事件一并发出，
   供后续消费者使用。
8. **后台提示语纠偏**：`§4.2` 首次隐藏的一次性提示原文写"点击托盘图标可再次打开
   工作台"，但托盘 `show_menu_on_left_click(false)`——左键什么都不做，实际入口是
   **右键托盘 → 「打开工作台」**（或全局快捷键/再次启动）。改为精确文案。

### 4. 协议变化

无 HTTP 协议变化；`get_core_connection` 描述符消费方新增"失败后重查"时序；
壳 → core 的每个 HTTP 请求新增 `x-owo-client: shell` 头（服务端已消毒）。

### 5. 权限与秘密影响

- 不放宽鉴权；`resetCoreConnection` 会一并失效注入 token 与缓存描述符，
  不会把旧凭据带到新代际。
- 壳拒绝来历不明的 core 可执行文件，属于**收紧**。

### 1. 本批唯一目标

### 2. 精确修改文件

### 3. 事实通道设计（为什么不能用别的口径）

- 请求预算：服务端 `/diagnostics/requests` 六字段台账（web/shell/probe 分桶，
  取证探测自身排除在统计外）。
- 界面状态：WebView2 **CDP** `Runtime.evaluate` 实读 DOM（专属
  `WEBVIEW2_USER_DATA_FOLDER`，否则与已安装版本共用浏览器进程组）。
- 可见性：**走产品自己的隐藏路径**（WM_CLOSE → tauri `window.hide()`），并用
  CDP 断言 `document.visibilityState === "hidden"` 真的翻转；恢复用第二实例
  唤回通道（§4.1），同时断言第二实例只唤回不另起。
- 产物一致性：壳构建时间必须晚于 `desktop/web/*`（壳**内嵌**前端资产，web 改了
  不重建壳就是在测上一版界面——`Assert-OwoShellEmbedsCurrentWeb`）；
  壳同目录 sidecar 副本按 SHA-256 与 staged 源对齐（tauri-build 只在构建壳时复制，
  重建 sidecar 不刷新它）。

### 4. 验收过程中被本批**推翻的两次假绿**（记录以免后人重踩）

1. `35/35 通过`但隐藏阶段从未执行：token 换发后隐藏阶段仍用旧 token 读台账 →
   401 抛断 → 脚本只在 `catch` 里打日志并 exit 0。修法：`catch` 必须登记
   `FAIL('断言链完整执行')`；隐藏阶段改用新一代 token。
2. "隐藏 5 分钟业务=0"是**靠断连蒙出来的**：修好重连后同一条断言立刻红
   （`health=10 business=5`）。顺着查下去发现两层原因：
   - 测试侧用 Win32 `SW_HIDE` 隐藏窗口，页面根本不认为自己也别隐藏；
   - 改走壳自己的 `window.hide()` 后，`document.visibilityState` **依然不变**
     （WebView2 不把 `SetIsVisible` 传导给页面）。
   也就是说这条产品需求此前从未真正实现过。修法分两侧：产品侧注入后台标记
   （R3.3 第 7 点），测试侧改为"触发壳隐藏命令 + 断言 `uiHidden()===true` +
   **在唤回之前**取 ledger 快照"（旧口径把恢复后的 deferred 补刷也算进隐藏窗口）。
3. 附带修掉的计数陷阱：PowerShell 函数返回会拆掉单元素数组，PS 5.1 下标量
   `.Count` 为 `null`，导致 `business ≤ 5` 拿着 null 空转通过
   （`web_business=null`）。修法：统一 `Get-OwoCount` + 台账事实新增
   `web_buckets_sum/web_buckets_ok` 自洽断言（四桶之和必须等于 `web_total`）。
4. 私有环境的**第二层泄漏**：`LOCALAPPDATA` 重定向能隔离核心数据根，但
   WebView2 的用户数据目录走 Windows known-folder API，不受它影响——不设
   `WEBVIEW2_USER_DATA_FOLDER` 时，验收壳与本机已安装版本共用同一个浏览器进程组，
   DevTools 端口/页面目标不可控（实测：`/json/version` 活着但取不到 DOM 事实）。
   修法：每轮验收使用专属 UDF，并以 UDF 下 `DevToolsActivePort` 为端口真相
   （指定端口被抢时 Chromium 会静默换口）。
5. 环境边界（影响可测性，不改产品）：本沙箱禁止子进程开命名管道，因此
   §4.1 的"第二实例唤回"无法作为验收驱动手段（第二实例会落入
   `InstanceLock` 致命错误分支并弹原生错误框）。唤回改由壳的
   `set_window_visible` 命令驱动——它与托盘「打开工作台」、全局快捷键共用同一
   `show_main_window` 实现；§4.1 单实例语义仍由 Rust 侧测试覆盖。

### 5. 权限、秘密、网络、不可恢复操作影响

- 两个验收脚本都以**私有运行根**执行：`LOCALAPPDATA/APPDATA/TEMP/WebView2 UDF`
  全部重定向到 `%TEMP%\owo-desktop-{coldboot,faults}-<stamp>`，不污染用户真实
  数据目录；断言 "token 文件落在本次私有数据根" 守护这一点。
- 模型密钥只从用户级环境变量注入子进程，绝不回显、绝不写入证据文件
  （AGENTS.md 红线）；读取 bearer 只用于本机 loopback 探测，证据 JSON 里
  不含 token 值（台账本身六字段白名单，结构上不可能含）。
- 故障矩阵会**临时改名** `target/debug/owo-agent.exe`（`binary-missing` 场景），
  `finally` 必恢复；清理进程只按命令行含本次私有根匹配，不碰用户会话中的同名进程。
- 无不可恢复操作：场景目录整体位于 `%TEMP%`，结束时删除。

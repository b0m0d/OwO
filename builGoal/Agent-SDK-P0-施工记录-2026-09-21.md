## 1. 施工前的代码理解（关键事实，先读懂再改）

1. **假通过的根因（F-08）**：旧 `scripts/mk-smoke.ps1` 第 22 行直接取
   `target\debug\owo-agent.exe` 运行，既不构建当前源码、也不比较 HEAD 与产物 build id。
   实测当时该 exe 自报 `commit=3f4bb03…`（M0），而 HEAD 是 `fc8251d…`（M15）——
   即 M15 的 18/18 是 M0 旧二进制跑出来的，证据链断裂。这是所有后续 PASS 失效的源头。
2. **身份单一事实源**：`crates/owo-build-info` 的 `identity()`（① `OWO_BUILD_INFO` 覆写
   → ② 编译期烧录 → ③ cwd `build-info.json`）。CLI `--version`、`core_ready.build_id`、
   server `/health.build`、`release-artifact-manifest.ps1` 全部同源，解析口径可直接复用。
3. **资源门已有可靠实现**：`scripts/ci-shared.ps1` 的 `Invoke-CiCargo` /
   `Invoke-CiLoggedCommand` 已内置内存门（<6 GB / ≥80% 拒绝）、磁盘门、构建空闲门、
   心跳、以及**运行中内存守护 + `taskkill /PID /T /F` 杀整棵进程树**，超时返回 124、
   资源越线返回 137、真实退出码经 `-PassThru` 透出。
4. **F-09 虚假参数**：`mk-tests-sharded.ps1` 声明了 `-ShardTimeoutMin`，但从未传给执行器，
   且注释里说"超时未实现"——是典型的"注释声称有门、代码里没有"。
5. **turn SSE 契约**：`POST /session/{id}/turn`（Bearer 鉴权）返回 SSE，事件
   `data:` 里的 JSON 带 `type` 字段：`token_delta` / `final` / `permission_request` / …
   （`owo-agent-protocol::SseEvent`，`SSE_PROTOCOL_VERSION=1`）。创建会话为
   `POST /session`，body `{ "workspace": "<path>" }`。
6. **出网开关**：`OWO_CLOUD_ENABLED=false` 会拒绝一切云端模型调用；基础 smoke 需要它来
   保证可复现，但**真实 turn 绝不能设 false**，否则必然失败。
7. **mock 与 real 必须分开**：ProductEval `execution=reference` 是确定性 dry 回放
   （零模型、零网络），属 mock 证据，不能计入真实模型闭环。

## 3. 施工记录（逐文件）

### 3.1 `scripts/ci-shared.ps1`（+91 行，新增身份唯一实现）

新增三个公共函数，供 smoke 与负例测试共用，**禁止各脚本各写一份解析**：

- `Get-CiGitIdentity`：`git rev-parse HEAD` + `git status --porcelain -uall -- .`，
  口径与 `release-artifact-manifest.ps1`、`build.rs` 一致（作用域 = `agent-sdk/`）。
- `Get-CiExeIdentity`：产物 SHA256 / 大小 / mtime + `--version` 自报的
  `commit/dirty/built_at/api/version`（证明"二进制自身主张"，而非脚本重新 git 查询的巧合）。
- `Test-CiBinaryIdentity`：身份门。commit 必须等于 HEAD；dirty 主张必须与 git 事实一致
  （与发布清单同口径）。返回 `{ok, reason}`，原因可直接进报告、供负例断言。

### 3.2 `scripts/mk-smoke.ps1`（重写，+295/-68）

- 参数：`-ExePath`、`-Build`、`-BuildPolicy`、`-RealTurn`、`-IdentityOnly`、
  `-ReadyTimeoutSec`、`-RealTurnTimeoutSec`。
- **身份门前置于任何进程启动**：先算源码身份与产物身份，不符 → 报告落盘 → `exit 3`，
  `started=false`（旧二进制不可能混进运行态验收）。
- `-Build`：经 `Invoke-CiCargo`（`-j 1`，`--locked`）构建 `owo-agent-cli`；资源门拒绝→4，
  编译失败→2。构建成功后才进入运行态门。
- `-IdentityOnly`：只跑到身份门就结束（离线、秒级），给负例测试当匹配态正例。
- 运行态门保留旧版全部真实检查（真实进程 + 真实 HTTP + 真实落盘），并新增
  `daemon.runtime_build_id_matches_head`（`core_ready.build_id` 与 HEAD 交叉核对）。
- 报告 `schema=owo-mk-smoke/2`：`source{commit,dirty}`、`binary{path,sha256,bytes,mtime,
  version,commit,dirty,built_at,api_version}`、`identity{ok,reason}`、`build{...}`、
  `real_turn{...}`、`checks[{check,pass,detail,evidence}]`。
- 退出码：0 通过 / 1 基础门失败 / 2 预检或构建失败 / 3 身份不符 / 4 资源门 / 5 真实 turn 失败。
- 真实 turn 模式**不再设** `OWO_CLOUD_ENABLED=false`；密钥经
  `[Environment]::GetEnvironmentVariable('OPENAI_API_KEY','User')` 注入本进程，仅打印
  `credential_present=true/false`，不回显密钥。

### 3.3 `scripts/real-turn-smoke.py`（新增）

- 用 `http.client` 对真实 Daemon 发 `POST /session` 建会话，再 `POST /session/{id}/turn`
  以 `text/event-stream` 逐行读取。
- 统计 `delta_count`、`first_delta_latency_s`、`stream_span_s`、`final_latency_s`、
  `final_received`，并给出 `buffered_suspected`（首 delta 与 final 几乎同时且占比 ≥90%
  ⇒ 疑似整轮缓存回放，即 F-02）。
- token 经环境变量 `OWO_SMOKE_TOKEN` 传入（不进入进程列表）；结果写 `--out` 供 PowerShell 读取。

### 3.4 `scripts/mk-tests-sharded.ps1`（+54/- 行，修复 F-09）

- 把 `$ShardTimeoutMin` 真正落成 `Invoke-CiCargo -TimeoutSec ($ShardTimeoutMin*60)`：
  超时由执行器 `taskkill /T /F` 杀 `cargo→rustc→link→测试进程` 整棵树、保留日志、返回 124。
- 保留"启动前资源门拒绝（抛异常）→ 记 137 并等待重试"的既有语义。
- 每分片记录 `reason`（passed / failed / timeout / resource_limited），并新增
  `docs/qa/logs/sharded-summary-<pkg>-<ts>.json`（真实退出码 + 原因，可事后区分三类失败）。
- 删除"超时未实现/不要用 Start-Job"的过时注释，改为说明唯一已验证路径与人工排查方法。

### 3.5 `scripts/test-mk-smoke-identity.ps1`（新增，负例契约测试）

- 用可执行的 `.cmd` 垫片模拟产物（离线、秒级，不依赖本机是否真有旧二进制）：
  - 负例：自报 commit≠HEAD → 断言 `exit=3`、`identity.ok=false`、`started=false`、
    报告含 binary commit/SHA256；
  - 正例：自报 commit=HEAD 且 dirty 与源码一致 → 断言 `exit=0`、`identity.ok=true`、
    `-IdentityOnly` 不启动进程；
  - 单元：dirty 漂移（产物 dirty=true、源码 clean）必须被拒。

### 3.6 `scripts/test-ci-shared-resource-policy.ps1`（+15 行）

- 新增超时门自测：`Invoke-CiLoggedCommand` 跑一个 60s 睡眠 + 3s 超时，断言返回 124，
  且无残留睡眠进程（精确用 `Win32_Process.CommandLine` 匹配），证明 sharded 依赖的
  超时确实杀树而非只停外层。

# OwO Agent V1 桌面端与系统代码系统性优化修复报告

> 审计日期：2026-08-31  
> 审计对象：`agent-sdk/` 当前工作树、当前桌面开发版、当前本地服务  
> 审计方式：真实桌面操作 + 当前源码检查 + 当前 Git/构建产物检查 + 本地 API 实测 + Rust 编译检查  
> 报告定位：指导后续修复，不把单元测试通过等同于产品可用

## 1. 结论

当前版本属于“核心能力已大量落地，但桌面产品层失控”的开发版，不能作为稳定日常 V1 使用。

问题不是单纯配色或间距，而是四类结构性缺陷叠加：

1. **信息架构错误**：会话、项目、工具、设置没有真正的页面路由；工具、评测、自动化、WorkSwarm、设置等被堆进同一个超长侧栏 DOM。
2. **导航状态机有确定逻辑错误**：项目按钮只聚焦路径输入框；设置按钮会被工具页状态立即覆盖；从工具页返回会话没有关闭工具页。
3. **网络层分裂**：部分页面使用带 token 的统一请求，旧面板和若干下载/删除/上传操作直接 `fetch`，在当前鉴权中间件下必然返回 401。
4. **桌面壳缺少服务生命周期管理**：固定端口、启动错误被吞、没有健康等待、没有版本匹配、没有启动恢复，导致首屏请求失败后留下永久错误。

WorkSwarm 并非没有实现。团队创建、列表、详情、任务 DAG、进度、Artifact、Human、ChangeSet、工作区绑定、恢复等代码确实存在；但入口被放在 14 个扩展按钮中的第 12 个，且嵌在三列工具页最窄的一列中，所以用户几乎无法发现和正常阅读。

## 2. 当前真实运行结果

### 2.1 桌面操作复现

在约 1280×800 的当前桌面窗口中复现：

- 首屏采用“88px 功能栏 + 会话栏 + 主区 + 检查器栏”的固定组合，主区大量空白，左右栏抢占主要宽度。
- 工作区输入框直接显示 `C:\Users\...` 绝对路径。
- “项目”点击后只让工作区输入框获得焦点，主内容不变。
- “工具”进入一个三列超长卡片页，同时加载技能、Eval、Traces、子代理、项目规则、MCP、插件、Computer-use、操作学习、自动化、白名单、扩展面板和设置。
- “设置”没有进入独立页面，只滚动到同一个工具页底部。
- 扩展面板按钮不换行，产生整页横向滚动；WorkSwarm 需要先向下滚动多屏，再横向滚动才能看到。
- 通过可访问性点击 WorkSwarm 时出现窗口外坐标错误；横向滚动后才能用坐标打开。
- WorkSwarm 团队列表和详情可读取真实数据，但表头、team_id、时间戳逐字折行，详情按钮贴边。
- 已完成团队同时显示“已成功”和“○ 未执行”，用户无法理解前者是历史终态、后者是当前进程没有活跃执行。
- 首屏和工具页出现 `Failed to fetch`、401；稍后顶部又显示“API 就绪”，页面没有自动恢复失败区块。

### 2.2 本地服务实测

服务就绪后，带鉴权访问以下端点均返回 200：

- `/health`
- `/sessions`
- `/skills`
- `/project/rules`
- `/whitelist`
- `/server/status`
- `/human/inbox`
- `/teams`

这证明大量 `Failed to fetch` 不是端点永久缺失，而是启动竞态和前端无恢复机制。

以下路径不带鉴权均返回 401，而当前前端对应操作恰好没有附带 token：

- `/learn/export/{name}`
- `/learn/import`
- `/automations/{id}`
- `/session/{id}/export/{format}`
- `/stt/transcribe`

### 2.3 构建与工作树

- `cargo check --offline -p owo-agent-core -p owo-agent-server` 当前通过。
- 桌面壳可构建并打开，但当前健康响应只有 `healthy/version/auto_approve`，没有 build commit，无法证明桌面壳和核心服务来自同一提交。
- 当前桌面 EXE 的构建时间晚于核心 EXE；核心服务仍可能运行旧于当前工作树的代码。
- 当前仍有未提交的多 Agent 收益策略和执行器改动，不能把它们视为已集成发布能力。

## 3. “之前的 UI 和美化做到哪里去了”

美化代码主要落在以下文件，且当前桌面构建已经加载：

- `agent-sdk/desktop/web/style.css`：主题、颜色、卡片、阴影、响应式、WorkSwarm/评测/Action Center 等样式。
- `agent-sdk/desktop/web/index.html`：功能栏、会话栏、工具表单、扩展面板、设置区。
- `agent-sdk/desktop/web/app.js`：主题、尺寸拖拽、工具/设置显示、面板挂载、API 调用。
- `agent-sdk/desktop/web/panels/*.panel.js`：各扩展面板。

近期 UI 提交大多是在 WorkSwarm 单文件和 `style.css` 上继续追加功能：

- 产品评测、实时进度、Artifact 评审；
- 组队策略、角色指标、版本时间线；
- Project Launcher、工作区绑定；
- Action Center、ChangeSet、项目历史。

这些工作没有消失，但采用了“继续向同一扩展面板追加按钮和卡片”的方式，没有重构顶层导航。结果是局部组件样式更精细，整体产品却更拥挤、更难找。现有前端测试主要验证 HTML 字符串、字段和点击处理器，不验证 1280×800 下的真实布局、可发现性和跨页面导航，因此“web 测试全绿”没有阻止当前视觉退化。

## 5. 逐项根因与修复设计

### 5.1 P0：重写顶层页面路由

#### 根因

`agent-sdk/desktop/web/app.js` 当前用 body class 模拟页面：

- `setSettingsPageVisible(true)` 先加入 `settings-open`，随后调用 `setToolsVisible(true)`；后者又主动移除 `settings-open`。
- 会话分支只调用 `setSettingsPageVisible(false)`，没有移除 `tools-open`。
- 项目分支只有 `workspace.focus()`，没有项目视图。

#### 修复方法

建立单一页面状态：

```text
route = chat | projects | workswarm | artifacts | settings
```

所有左侧按钮只调用 `navigate(route)`；`navigate` 负责：

- 切换唯一 active route；
- 显示唯一主视图；
- 更新标题、面包屑和说明；
- 保存最后页面，但不保存瞬时滚动位置；
- 取消离开页面后的轮询/SSE；
- 将焦点放到页面主标题，而不是隐藏输入框。

#### 修改文件

- 修改 `agent-sdk/desktop/web/app.js`
- 修改 `agent-sdk/desktop/web/index.html`
- 修改 `agent-sdk/desktop/web/style.css`

- 页面切换不依赖 `scrollIntoView`。

### 5.3 P0：统一 API 客户端并修复所有 401

#### 根因

主应用只有 `api/get/post`，缺少通用方法；各面板因此各写一套 `fetch`。当前确定绕过鉴权的功能包括：

- 技能包导出/导入；
- 自动化删除；
- 会话导出；
- STT 上传；
- 旧统一命令、记忆、Goal、可观测性、插件市场、Team、Fleet 面板；
- 笔记删除和重命名。

#### 修复方法

新增唯一的 `ApiClient`：

```text
request(method, path, {json, body, responseType, signal})
get / post / put / patch / delete
upload / download / stream
```

统一处理：

- token 获取、缓存、401 后单次刷新；
- JSON/Blob/Text/SSE；
- `AbortSignal`；
- trace id；
- 错误码和中文错误；
- 连接状态广播；
- 幂等 key 注入策略。

面板不得直接调用 `fetch`，测试增加静态守卫。

### 5.4 P0：服务启动与错误恢复

#### 根因

Tauri `spawn_core_server()` 使用固定 4096 端口并以 `.spawn().ok()` 吞掉启动错误；页面加载后立即并发刷新二十多个模块。连接失败进入 5 秒冷却，但会话、技能、白名单、项目规则等没有健康恢复刷新，因此错误永久残留。

#### 修复方法

桌面壳启动流程：

1. 检查 4096 是否已有 OwO 服务，读取 `/health.build` 和实例 id。
2. 若版本兼容则附着，不重复启动。
3. 若端口被其他进程占用，申请空闲端口并通过 Tauri 配置注入前端。
4. 启动子进程后等待健康，采用 100/200/400/800ms 有界退避，总时限 10 秒。
5. 启动失败显示独立故障页，展示脱敏诊断和“重试服务”按钮。
6. 核心退出时通知前端并允许一次受控重启。

前端连接恢复时触发一次 `refreshCriticalSurfaces()`，刷新会话、技能、项目规则、白名单、Inbox、Teams 和存储状态。

#### 修改文件

- `agent-sdk/desktop/tauri/src-tauri/src/main.rs`
- `agent-sdk/desktop/tauri/src-tauri/tauri.conf.json`
- `agent-sdk/desktop/web/app.js`
- `agent-sdk/crates/owo-agent-server/src/lib.rs`
- `agent-sdk/crates/owo-agent-protocol/src/lib.rs`（若增加实例/构建握手字段）
- OpenAPI 与 TS 契约快照

#### 新增文件

- `agent-sdk/desktop/web/views/service-error.view.js`
- `agent-sdk/desktop/tauri/src-tauri/src/core_supervisor.rs`

#### 完工要求

- 冷启动期间不显示 20 个 `Failed to fetch`。
- 服务晚启动 1–5 秒时页面自动恢复，无需重开应用。

### 5.5 P0：把 WorkSwarm 做成真正的产品主流程

#### 当前问题

- WorkSwarm 是扩展面板按钮，不是一级页面。
- 创建、列表、模板、详情、SSE、Artifact、审批、工作区、诊断全部在一个 4600 多行文件中。
- 技术字段太多，缺少“目标—成员—进度—待处理—产物”的用户叙事。
- 历史终态与当前活跃标志混用，出现“已成功/未执行”。

#### 修复后的页面

WorkSwarm 首页分四区：

1. 运行中：目标、阶段、成员、预计下一步、停止。
2. 待我处理：Human、Artifact 评审、ChangeSet、失败重试。
3. 最近完成：结果摘要、最终 Artifact、耗时、模型调用量。
4. 新建团队：模板、目标、角色、工作区权限预览。

团队详情固定结构：

```text
目标与结果
成员与当前工作
时间线/DAG
待处理事项
Artifacts 与 ChangeSet
运行数据与诊断（折叠）
```

状态文案统一：

- 历史成功 + 当前无进程：`已完成`，不显示“未执行”。
- 已创建未开始：`等待启动`。
- active=true：`运行中`。
- interrupted=true：`意外中断，可恢复`。
- AwaitingHuman：`等待你处理`。

### 5.9 P1：本地鉴权边界收紧

#### 风险

- `/auth/token` 是公开端点。
- CORS 接受任意端口的 `localhost`、`127.0.0.1` 和 `tauri.localhost`。
- 任意以 localhost 运行的本地页面在该边界内都可能读取 token，token 更像“阻止普通远程网页”的屏障，而不是严格的桌面客户端身份认证。
- `is_sse_path` 对任何以 `/events` 结尾的路径免鉴权，规则过宽。

#### 修复方法

- 桌面版通过 Tauri command/IPC 获取启动会话 token，不再让 Web 公开读取长期 token。
- token 使用短期会话能力，绑定 desktop instance，并支持核心重启轮换。
- 开发浏览器模式单独启用显式 dev token，不与发布版共用策略。
- SSE 豁免改为精确路由白名单；能用带 header 的 fetch-stream 时不豁免。
- CORS 发布版只允许实际 Tauri origin；localhost 仅 dev feature 开启。

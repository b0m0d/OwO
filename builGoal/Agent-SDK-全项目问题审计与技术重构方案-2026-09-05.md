## 3. 当前必须先处理的真实缺口

### 3.1 自动化门禁并未全绿

#### 前端 6 项失败

当前 292 项前端测试中有 6 项失败，主要是模块拆分后测试仍读取旧 app.js，另有字段和文案断言没有同步：

1. action-center.panel.test.mjs 仍要求旧文案“团队 awaiting_human”，实现已经改为“团队等待人工处理”。
2. Action Center 和 Project History 的接线守卫仍在 app.js 查找 PANEL_ORDER，实际已迁入 app-domain.js。
3. api-client.test.mjs 没有接受连接诊断新增的 expectedBuildId 字段。
4. ui-ia-fixes.test.mjs 仍在 app.js 查找 describeApproval() 和 refreshWhitelist()，两者实际已迁入 app-domain.js。

这些失败以测试随模块拆分漂移为主，但修复并重跑之前不能称为前端全绿。

#### 路由契约 2 项失败

1. /openapi.json 已提供 /capabilities、/mcp/enabled、/mcp/health、/mcp/reconnect，但 clients/ts/openapi.json 未同步。
2. SSE 续传测试直接搜索未转义的 domain 字符串；实际 domain 位于外层事件 JSON 的字符串字段 data 中，应解析两层 JSON 后断言。

#### TUI 快照 3 项失败

snapshot_cells() 逐 cell 拼接 TestBackend buffer。中文宽字符占两个终端单元，当前提取方式可能把 continuation cell 一并拼入，导致“空闲”“运行中”“新增行”断言失败。必须先修正快照提取，再判断是否存在真实布局回归。

#### Git 文本门禁失败

git diff --cached --check 报告以下文件末尾新增空行：

- desktop/web/app-domain.js
- desktop/web/shell/connection.js
- desktop/web/shell/markdown.js
- desktop/web/shell/speech.js

### 3.2 构建链仍不自包含

.cargo/config.toml 已消除原先的 CRT 冲突警告，但 cargo test 在新进程中仍不能自动找到 ONNX Runtime。当前只有手工设置 ORT_LIB_PATH 后才能链接。开发脚本、Cargo、CI、测试和桌面 sidecar 还没有共享同一个依赖解析入口。

### 3.3 暂存集过大且缺少提交边界

128 个文件同时暂存导致 CLI 拆分、server 路由、Agent 并发、Web UI、Tauri、构建脚本和文档混在一起。任一测试失败时难以定位来源，当前 release core 也无法由某个 Git commit 唯一复现。

### 3.4 桌面和发布层仍未完成

- 尚未用真实 Tauri WebView 证明冷启动请求不超过 5、隐藏窗口业务请求为 0。
- 尚未完成三视口、125%/150% 缩放和错误页人工验收。
- 默认配置仍可能引用未随产品分发的示例 MCP server。
- CSP 仍包含 script-src unsafe-inline，updater 地址仍是 example.com。
- 桌面 EXE、sidecar、Web、core 和 manifest 尚未证明来自同一个 clean commit。
- 新安装包生命周期 E2E 和与 Codex 的同任务对标尚未开始。

## 4. 后续执行总原则

1. 先恢复门禁，再整理提交，再做桌面验收。当前不得继续堆叠新功能。
2. 每个执行包只解决一类问题。测试修复、机械拆分、行为修改、发布配置不得混在同一提交。
3. 路由变化必须同步 server route、route_contract_tests.rs、OpenAPI/TS 快照。
4. 不降低安全边界换性能。并发、缓存、重试和自动批准继续使用 ToolEffect、permission profile 和审计链。
5. 产物只能从 clean commit 构建。dirty tree 只允许开发验证。
6. 真实桌面是独立验收门。进程存在、端口监听、/health 和浏览器模拟不能代替可见窗口验收。
7. 保留用户现有工作。组织暂存集前先记录文件清单和补丁摘要，不批量删除仓库外资产。

后续依赖顺序固定为：

R0 当前门禁收口 → R1 暂存集拆分 → R2 构建与 ORT 自包含 → R3 真实桌面 → R4 UI 与权限验收 → R5 性能闭环 → R6 结构深化 → R7 安全发布 → R8 安装包 E2E 与 Codex 对标。

## 7. R2：构建身份与 ORT 自包含

### 7.1 统一 build metadata

现有 owo-build-info 应成为 CLI、server 和 Tauri 唯一事实源。结构至少包含 commit、built_at、dirty、api_version。

- 删除 CLI/server 重复的 build metadata 逻辑。
- /health、--version、doctor 和 release manifest 使用同一结构。
- built_at 从编译期常量读取并校验 RFC3339；正式构建不得为空。
- Tauri 壳嵌入 expectedBuildId，连接 descriptor 同时报告 expected/actual；不一致时显示错误页。

### 7.2 统一 ORT 解析入口

新增 scripts/resolve-ort.ps1，只负责：

1. 优先使用调用者显式设置的 ORT_LIB_PATH。
2. 检查仓库固定缓存目录和已知 sherpa 预构建布局。
3. 校验目录内实际存在所需 .lib，记录版本和 CRT 类型。
4. 只向当前构建进程注入路径，不写用户永久环境变量。
5. 找不到时立即报可操作错误，不等到链接阶段。

开发构建、测试、CI、desktop sidecar、installer 必须调用同一入口。若需要支持裸 cargo test，则应把 ORT 放到稳定仓库相对目录并通过 Cargo 配置注入，不能依赖 target 中偶然存在的缓存。

### 7.3 发布构建约束

- 新终端不预设 ORT/ONNX 变量，通过统一脚本完成 debug 和 release。
- LNK1120、LNK4098 和 linker warning 均作为发布失败。
- release 入口拒绝 dirty tree。
- manifest 包含 commit、built_at、依赖版本和 artifact SHA-256。

建议提交：build: make identity and ORT resolution reproducible。

完成证据：空环境构建成功；debug/release/sidecar 身份一致。

## 8. R3：真实桌面连接、冷启动与错误恢复

这是解决“桌面端一直是空壳”的核心执行包，不能再用浏览器模拟代替。

### 8.1 安全请求记录

Tauri/core 开发诊断只记录 method、route_template、started_at、duration_ms、status、source。禁止记录 Authorization、pairing secret、请求体、响应体和完整私人路径。

### 8.2 全新数据目录冷启动

依次验证：

1. 桌面壳启动 sidecar。
2. 壳等待 generation-bound ready，取得动态端口、instance id、build id 和内存 token。
3. WebView 在第一个受保护请求前取得 connection descriptor。
4. 首次可输入前真实 HTTP 总数不超过 5。
5. core 重启后旧 token 失效，只重新引导一次，不形成双事件连接。
6. 窗口隐藏 5 分钟，业务请求为 0，只允许明确记录的 health。

若请求超过 5，按“首屏是否可见必需”继续推迟 skills、whitelist 或 project rules，禁止用并发数冒充总请求数。

### 8.3 失败矩阵

覆盖 sidecar 缺失、core 超时、端口冲突、数据目录不可写、token 失效、build id 不匹配、provider 未配置、示例 MCP 缺失。错误页说明发生了什么、系统尝试了什么、用户下一步怎么做；技术细节折叠。

生产 profile 不得默认启用 owo.plugin.example-hello 等测试 MCP。

完成证据：900×600、1280×720、1920×1080 和 125%/150% 缩放有截图；双击后 10 秒内出现可操作主界面或错误页；无永久 loading 和空白壳。

建议提交：test(desktop): verify real boot, reconnect and visible failures。

## 10. R5：工具调用、取消与 MCP 性能闭环

现有并发、DeadlineBudget 和 MCP 熔断代码已经存在，下一步重点是实测和补齐传递边界。

### 10.1 可信只读并发

- 用两个可控延迟只读工具证明总耗时接近最大单项耗时。
- 同一路径读写、两个写工具、未知 MCP、未宿主验证的只读 MCP 必须串行。
- 并发结果按原 tool-call 顺序回填；大结果写 artifact store。

### 10.2 取消和 deadline

- cancellation token 从 turn 入口传到 model、tool、MCP、子进程和持久化阶段。
- retry 前重新读取剩余预算，不能重新获得完整超时。
- 真实 HTTP 提交运行中任务，1 秒后取消，确认子进程和 MCP 停止且不继续写文件。
- trace 记录 model first-token、model total、approval wait、tool queue、tool run、persistence、cancel latency。

### 10.3 MCP 故障注入

模拟连接超时、调用超时、schema 变化、超大结果、连续失败开路和半开恢复：

- 故障 server 不阻塞其他 MCP 和内置工具。
- 开路后快速失败。
- 只有 idempotent=true 且确认远端未执行才自动重试。
- schema hash 变化后撤销只读信任、cache 和 grant。
- UI 显示 Ready/Degraded/OpenCircuit、最近错误、p50/p95 和重连。

完成证据：固定基准报告包含并发收益、取消延迟、MCP p95 和失败率；慢对话可从 trace 明确归因。

## 12. R7：安全配置与正式发布链

### 12.1 CSP 与 updater

### 12.2 不可变发布清单

manifest 至少包含 version、git_commit、built_at、dirty=false、api_version，以及 desktop/core/sidecar/web_assets 的 SHA-256。

发布入口拒绝 dirty tree；复制 sidecar 后立即校验 hash；安装包内嵌 manifest；诊断页显示组件是否一致，但不显示密钥或私人绝对路径。

### 12.3 新安装包

只能从 R0～R6 全绿后的 clean commit 构建。验证安装目录中的桌面 EXE、sidecar、Web、manifest、签名和源码 commit 一致，禁止复用 2026-09-02 旧产物。
